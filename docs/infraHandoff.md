# Infrastructure handoff — cost controls

No AWS settings or credentials were accessed or changed. Recommended launch settings:

- **AWS Budgets:** create a $100/month CloudFront budget, with actual-spend email/SNS alarms at $25, $50 and $80 and a forecast alarm at $100. Add a separate $300/month whole-account budget with actual alarms at $150, $240 and $300 and a forecast alarm at $300. If adopting the $200 Business flat-rate plan, use a $250 CloudFront budget with $200/$225/$250 actual alerts and a $250 forecast alert, and increase the account budget to $500 with $300/$400/$500 actual alerts. These are proposed launch envelopes, not a price estimate; adjust the fixed-cost portion after reviewing the current bill. Route alerts to someone able to pause public traffic. Budgets are delayed notifications, not spending caps. [AWS Budgets documentation](https://docs.aws.amazon.com/cost-management/latest/userguide/budgets-managing-costs.html).
- **WAF:** attach a rate-based Block rule to this distribution, aggregate by source IP (not a client-supplied forwarded header), scoped to `/api/*`, at **6,000 requests per 60 seconds**. This leaves room for 60fps playback while blocking sustained floods. Return **429**, JSON `{"error":"Too many requests. Please wait a minute."}`, and **Retry-After: 60**. Add a second rule scoped to `/api/upload` at **10 requests per 300 seconds**. Confirm shared-network behavior in Count mode during controlled testing, then switch to Block before public launch. WAF timing is approximate; nginx and persistent daily budgets remain necessary. [AWS WAF windows](https://aws.amazon.com/about-aws/whats-new/2024/03/aws-waf-rate-based-rules-configurable-time-windows/), [rate-rule caveats](https://docs.aws.amazon.com/waf/latest/developerguide/waf-rule-statement-type-rate-based-caveats.html).
- **CloudFront flat-rate plan:** AWS currently promises no overage charges even for spikes/attacks, but the cap covers the subscribed distribution and included services, not the AWS account. Origin compute, disks, S3 requests/storage beyond credits, and other excluded services still need budgets. For the existing VPC-origin architecture, evaluate **Business ($200/month) or higher**; lower tiers do not include VPC origins. Verify eligibility, exact monthly price, included WAF rules, allowance/performance-adjustment terms, and that the subscription is active on the correct distribution before relying on it. Verify no alternate pay-as-you-go distribution or public origin can serve the same traffic. Do not interpret “no overages” as guaranteed performance or a whole-account cap. [AWS plan coverage and VPC-origin tier table](https://docs.aws.amazon.com/AmazonCloudFront/latest/DeveloperGuide/flat-rate-pricing-plan.html), [current pricing](https://aws.amazon.com/cloudfront/pricing/).
- **Cache and identity prerequisites:** keep `/api/*` edge caching disabled (minimum TTL **0**), forwarding session cookies, CSRF headers and all frame query parameters. Never override `private` with a positive minimum TTL. Static asset behaviors may cache for **31,536,000 seconds**, including `v` in their cache key. Preserve the VPC-origin restriction and CloudFront-generated `CloudFront-Viewer-Address` header; nginx strips its port to budget per viewer IP. Verify these headers reach nginx and Flask, and the origin is inaccessible directly. The supplied nginx config assumes this existing trust boundary.

Deployment prerequisite: install a vetted `ffprobe` executable in the service PATH and install the updated Python requirements before rollout. The Beanstalk predeploy hook checks it. Reinstall bundled examples through the normal bundle deployment: legacy shared templates are rebuilt as WebP; existing visitors retain their immutable JPEG frames until normal expiry. Uploads/annotations still expire after seven days; previously downloaded browser cache entries can remain until their own seven-day TTL expires.
